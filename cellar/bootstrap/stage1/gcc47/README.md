# Native GCC 4.7.4 bootstrap

All three native static C/C++ compiler stages and their target runtimes build.
The final driver, front ends, libgcc, libgcov and libstdc++ are available through
the stage1 installation. The graph retains every predecessor and generator.

BUILD owns the source manifest, configurations, immutable transformations,
generator tools, ordered table assembly and comparisons. All explicit rule
imports remain in cellar. GNU tar 1.12 extracts the pinned archive using numeric
ownership; no configure or Make process runs. Each compiler stage will rebuild
its generators with its predecessor, using stable logical source paths.

GCC 4.7 provides `makeucnid.c`, so the old Perl transformation is unnecessary.
Its inputs are the pinned Unicode 4.0.1 character and normalization data plus
GCC's handwritten `ucnid.tab`. The output matches the shipped `ucnid.h` exactly
after updating the generator's copyright string to preserve the header's 2009
notice. A bounds fix also avoids an out-of-range read after its final table row,
without changing the generated bytes. The CRC generator is extracted from its
explanatory source comment;
the regenerated table is assembled with the surrounding handwritten code and
matches the complete published file.

The decimal generator and preamble come from live-bootstrap revision
`dd8ac27bf959344b9bcf5e876bdd7716879bbc70`,
`steps/gcc-4.7.4/files/decDPD_generate.c` and `decDPD.h.preamble`.
Cellar fixes three defects: eight-bit parameter truncation for values above 255,
omitted partial output rows, and uninitialized/noncanonical DPD entries. All
19651 values across its nine generated tables match the shipped table values.
The original generated files are comparison fixtures, never compiler inputs.
Upstream notices and licenses are retained.

An additional C generator reconstructs `bid2dpd_dpd2bid.h` from the regenerated
DPD mappings and rounded-up power-of-ten reciprocals computed with GMP. It
preserves the upstream precision choices, including their exceptional entries.
All 11288 values across the 15 reciprocal, scale and digit-conversion tables
match the published values. Only the original license preamble is reused.

The native support libraries now build from 56 libiberty, 15 libcpp and nine
libdecnumber translation units, with a reviewed LP64 musl configuration.
Libdecnumber uses the x86 BID format and the regenerated conversion tables.
Libiberty requires an explicit writable `TMPDIR` instead of falling back to a
host directory. Ten tests cover table regeneration, demangling, MD5/SHA1/CRC,
argument parsing, obstacks, hash tables, regular expressions, child processes,
temporary files, preprocessing and Unicode conversion, missing includes,
decimal arithmetic/rounding, and decimal32/64/128 conversions.

Four upstream C generators now produce the native machine-mode definitions,
tree-code checks for C/C++, RTL constructors and the three target-hook headers.
The generated minimal mode table is compiled and exercised for 64-bit integers,
x87/quad floating point, vectors and decimal modes. The pinned musl target
patches are applied as exact immutable transformations; their original notices
are retained in `patches/`.

The x86 machine-description pipeline now regenerates options, builtin types,
predicates, constraints, instruction tables and scheduling automata. It compiles
and runs `gencondmd` to evaluate conditions before instruction generation. The
garbage-collector generator uses a regenerated Flex scanner and GCC 4.7's
handwritten parser; separate actions write and read its type state. Its explicit
C/C++ inventory includes generated option structures and produces 73 files.
Source and condition paths remain stable across stages. Thirteen tests now pass,
including actual RTL construction/copying, constant and deferred condition
evaluation, and malformed machine-description diagnostics.

The compiler graph declares 377 translation units for the shared backend,
common libraries and C/C++ front ends, plus separately compiled zlib and
checksum objects. GCC's actual checksum generator consumes ordered object and
library artifacts. All compiler sources use stable logical paths. The native
configuration uses the standard target-header guards, GNU assembler CFI and
COMDAT support, and shared LTO option declarations while leaving LTO and
plugins disabled. The first-stage compiler accepts older GCC's diagnostic
attribute warnings, as upstream's bootstrap does; subsequent compared stages
use the same stricter flags. The conservative reference patch removes the
gperf-generated C++ library-name lookup without substituting generated code.

Twenty-eight tests pass, including C and C++ execution at both `-O0` and `-O2`,
templates, constexpr expressions, lambdas, multiple inheritance and virtual
dispatch, local object lifetimes, native atomics, startup, pthreads, math,
Unicode, malformed C/C++ input and missing declared headers. These front-end
tests link the existing C runtime. C++ exceptions, RTTI and standard-library
acceptance are covered by the separate libstdcxx package.

The drivers use native GNU assembler/linker paths supplied through `-B`, static
link specifications and an explicit header inventory, including x86 intrinsic
headers. A missing compiler or assembler is fatal even with host directories
on `PATH`. Thirty-four tests pass, adding ordinary and piped driver compilation,
C++ dispatch, preprocessing and missing-tool diagnostics. `stage1-bootstrap-gcc`
is the compiler interface for building the new target runtime; it does not
depend on that runtime, avoiding a cycle.

Process tracing exposed `/dev/urandom` reads in three negative front-end tests
that omitted `-frandom-seed`. Those tests now use the same fixed seed as build
actions. The corrected gate at `4446143b` found no boundary violations and
seven identical static compiler/driver executables across workspace paths.

The target runtime now builds with the newly built compiler: 221 libgcc
objects, 18 libgcov objects and six startup/support objects. It includes
128-bit integer helpers, x87/complex arithmetic, soft binary128, all three
decimal BID widths, DWARF unwinding, emulated TLS support and coverage.
The native musl adaptations use `ucontext_t`, enable `dl_iterate_phdr` unwind
lookup and use strong pthread references. Split stacks are rejected because
the upstream x86 implementation assumes glibc TLS storage. Ordinary musl
threading and stack protection remain enabled.

Forty-five tests pass. The runtime gate exercises static driver linking,
constructors/destructors, 128-bit division/conversion, complex and extended
floating point, decimal conversions, concurrent arithmetic, forced unwinding,
signal-frame unwinding and pthreads. A coverage test compiles and links an
instrumented program, runs it, invokes the new gcov and checks execution counts.
Missing libraries and the unsupported split-stack option produce errors.

```
buck2 test cellar//bootstrap/stage1/gcc47: --local-only -j 8
```

The graph now instantiates all three GCC stages. Every generator and compiler
executable is built with the predecessor compiler and links that predecessor's
runtime. Each newly built GCC builds its own libgcc, libgcov, CRT and C++
libraries. Compared builds use identical logical source paths, deterministic
archives, fixed time macros, fixed random seeds, and no debug information.
Libcpp's GCC-4.7-only vector scanner declares its CPUID header explicitly. A
redundant extern specifier is removed from the language-mask definition so
later C bootstrap stages can retain -Werror without changing linkage.

The combined GCC/C++ gate passes 1007 tests. Stage2 and stage3 compare 522 host
compiler/generator objects, 245 target C runtime objects and 124 C++ runtime
objects byte-for-byte, plus the four target runtime archives. Only
`cc1-checksum.o` and `cc1plus-checksum.o` are excluded. This is an upstream-style
object comparison, not a claim of executable identity. The execution checks
also cover both later stages' arithmetic, unwinding, pthreads, coverage, C++
exceptions, RTTI, standard library and streams at both optimization levels.

The host-side `audit-gcc-comparison.py` checks the comparison inventory against
Buck's actual object targets, separately from running the byte comparisons:

```
buck2 uquery 'kind("c_object", set(cellar//bootstrap/stage1/gcc47: cellar//bootstrap/stage1/libstdcxx:))' --json > /tmp/gcc-objects.json
buck2 uquery 'kind("command_test", set(cellar//bootstrap/stage1/gcc47: cellar//bootstrap/stage1/libstdcxx:))' --output-attribute=args --json > /tmp/gcc-tests.json
python3 cellar/bootstrap/audit-gcc-comparison.py --objects /tmp/gcc-objects.json --tests /tmp/gcc-tests.json
buck2 test cellar//bootstrap/stage1/gcc47:stage-comparison cellar//bootstrap/stage1/libstdcxx:stage-comparison --local-only -j 8
```

The driver adds upstream's x86 math startup files: `crtfastmath.o` for
`-Ofast` and `-ffast-math`, and `crtprec32.o` to `crtprec80.o` for `-mpc32` to
`-mpc80`. Each stage checks the floating-point modes a program starts with by
default, with `-ffast-math` and with `-mpc32`, and the combined gate passes
1007 tests.

The native option inventory includes upstream `gnu-user.opt`, alongside the
x86, Linux and Android option files. This supplies the ordinary `-pthread`,
`-posix`, `-profile` and `-rdynamic` driver switches. The installation gate found
that omission even though direct pthread runtime tests already passed. Each
GCC stage now verifies `-pthread` preprocessing (`_REENTRANT`) and execution;
C++ thread tests use the same option at both optimization levels. The corrected
combined gate passes 1010 tests, retaining all 891 object and four archive
comparisons and the same two checksum exclusions.
