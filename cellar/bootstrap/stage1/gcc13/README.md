# Native GCC 13.5.0 bootstrap

GCC 13 follows GCC 10.5.0 and binutils 2.41 on live-bootstrap's route; this
package builds the 13.5.0 point release. GCC 13 is written in C++11, so GCC
10's C++ compiler and libstdc++ build the first stage. BUILD declares the
source, configuration, generators, compilers, drivers and target runtime for
three stages, as the [GCC 10 port](../gcc10/README.md) does. No configure or
Make process runs.

The pinned archive uses pax headers, so the bootstrapped
[pax extractor](../pax/README.md) unpacks it. Small support directories are
projected whole. `sources.bzl` lists the `gcc/` sources the C and C++
compilers and the x86_64 target can read, and the libcpp, libdecnumber and
libcody files, withholding the files BUILD regenerates. Every `gcc/` and
libcpp source is C++ and named `.cc`.

## Regenerated sources

Shipped generated files are comparison fixtures, never compiler inputs. All
Unicode inputs are the 15.0.0 files GCC ships in `contrib/unicode`.

- `libcpp/ucnid.h` is regenerated by GCC's `makeucnid`, which now also reads
  the XID properties C++23 identifiers use. It matches the shipped file byte
  for byte; the GCC 10 port's bounds fix still applies.
- `libcpp/uname2c.h`, new in GCC 13, maps Unicode names to code points for
  `\N{...}` escapes. GCC's `makeuname2c` regenerates it, sorting its radix
  tree stably as the release's glibc build did, and it matches byte for byte.
- `libcpp/generated_cpp_wcwidth.h` comes from `generators/wcwidth.c`, the
  GCC 10 port's C reimplementation of GCC's Python generator, updated for the
  GCC 13 rule that only assigned Hangul jungseong and jongseong are zero
  width. It matches byte for byte.
- The CRC table in `libiberty/crc32.c`, the DPD and BID decimal tables and
  gengtype's scanner are regenerated as in the GCC 10 port.
- `cp/cfns.h` and the new `cp/std-name-hint.h` are gperf output upstream.
  The GCC 10 port's `gperf.awk` writes an equivalent sorted table and
  bisecting lookup for either input with the bootstrapped awk. Tests check
  that each holds the same names as the shipped gperf lookup, agrees with it
  for every name, and rejects the same near misses.

`version.h` comes from GCC's `genversion`, which replaces the GCC 10
`gcov-iov` generator. Option records, pass instances and the x86 builtin
types come from GCC's awk scripts. See [patches](patches/README.md).

## Configuration

The configuration headers are written as `gcc/mkconfig.sh` would write them
for x86_64 musl, as in the GCC 10 port. `auto-host.h` is a reviewed list of
`gcc/config.in` values for a native musl 1.2.5 host with GNU binutils 2.41.
The differences from GCC 10 follow the new probes and binutils:

- The assembler and linker compress debug sections with zlib (level 1); GCC
  13 counts zstd as level 2, which the cellar binutils do not support.
- gas 2.41 accepts `--gdwarf-5` and writes the line table from the
  compiler's `.file` and `.loc` directives, so the driver passes `--gdwarf-N`
  for every `-g` compile.
- ld no longer supports `-z bndplt`, and GCC 13 no longer emits stabs.
- musl 1.2.5 declares `basename` only in `<libgen.h>`, so libiberty.h
  declares it. The calls, such as gcov's, reach musl's POSIX `basename`, as
  in an upstream musl build.

As in the GCC 10 port, only the C, C++ and LTO option files and the C and
C++ tree codes and garbage collector roots are included; `multilib.h`
describes one native library directory; the driver's specs accept only
static native executables; and `ld` is never passed `--sysroot`. GCC 13
already rejects split stacks for musl, and `tm.h` also removes the thread
offset so that `-mglibc` cannot enable them.

## Compilers and runtime

Each stage builds its own support libraries, generators and compilers from
the same sources. The first stage is built by GCC 10's `g++` and libstdc++;
each later stage by its predecessor's GCC 13 and libstdc++ 13. As upstream,
each stage keeps its compiler's default C++ dialect, and later stages add
`-Werror`. The compilers link GMP, MPFR, MPC, zlib 1.2.12 from the binutils
2.41 port and libbacktrace, and `cc1plus` also links libcody for C++20
modules. `cc1` and `cc1plus` allocate through [mimalloc](../mimalloc/README.md)
instead of musl's malloc, which unmaps and remaps pages hundreds of
thousands of times per large translation unit. Their output is unchanged,
and stages 2 and 3 compile about 15% faster, LLVM about 7%. The static
analyzer is enabled, as it is upstream.

The new driver builds libgcc, libgcov and the startup objects with
upstream's flags for x86_64 Linux: 267 libgcc objects, including the half
precision and bfloat16 conversions GCC 13 adds, 28 libgcov objects, and
`crtbeginT.o`, `crtend.o`, `crtprec{32,64,80}.o` and `crtfastmath.o`.
As upstream, the driver links `crtfastmath.o` for `-Ofast`, `-ffast-math` and
the new `-mdaz-ftz`, and the `crtprec` objects for `-mpc32` to `-mpc80`. The
signal-frame unwinder is enabled for musl, as in the GCC 10 port.

The C++ standard library is in [libstdcxx13](../libstdcxx13/README.md).

## Tests and stage comparison

Each stage's compiler, driver and runtime pass the GCC 10 port's execution
tests, which this package shares, plus a C program built with `-g` through
the assembler's DWARF 5 path and one built with `-mdaz-ftz`. Each stage's
debug line table must map `main` back to its C source line. A coverage test
compiles, runs and reports an instrumented program with each stage's gcov.

Stage2 and stage3 compare byte for byte: 781 host objects (support
libraries, generators, compilers, drivers and zlib), the 267 libgcc and 28
libgcov objects, the six startup objects and eleven archives, together with
the 196 libstdc++ objects and four archives. Only `cc1-checksum.o` and
`cc1plus-checksum.o` are excluded. The combined gate passes 1477 tests.
`audit-gcc-comparison.py` checks the comparison inventory, run as in the
[GCC 4.7 port](../gcc47/README.md) over this package and `libstdcxx13`.

```
buck2 test cellar//bootstrap/stage1/gcc13: cellar//bootstrap/stage1/libstdcxx13:
buck2 test cellar//bootstrap/stage1/gcc13:stage-comparison cellar//bootstrap/stage1/libstdcxx13:stage-comparison
```
