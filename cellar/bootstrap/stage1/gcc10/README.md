# Native GCC 10.5.0 bootstrap

GCC 10.5.0 is the next compiler after GCC 4.7.4, following live-bootstrap's
route. GCC 10 is written in C++98, so GCC 4.7's C++ compiler and libstdc++ can
build it, and GCC 10 in turn can build compilers that need C++11. BUILD
declares the source, configuration, generators, compilers, drivers and target
runtime for three stages. No configure or Make process runs.

The pinned archive uses pax headers for long member names, which tar 1.12
cannot read, so the bootstrapped [pax extractor](../pax/README.md) unpacks it.
Small support directories are projected whole. `sources.bzl` lists the `gcc/`
sources the C and C++ compilers and the x86_64 target can read, and the libcpp
and libdecnumber files, withholding the files BUILD regenerates.

## Regenerated sources

Shipped generated files are comparison fixtures, never compiler inputs.

- `libcpp/ucnid.h` is regenerated by GCC's own `makeucnid` from the Unicode
  6.3.0 data it was last generated from, and matches the shipped file byte for
  byte. A bounds fix stops its final flush reading past the tables.
- `libcpp/generated_cpp_wcwidth.h` is produced upstream by a Python script
  over glibc's `utf8_gen.py`. `generators/wcwidth.c` reimplements both in C,
  reading the Unicode 12.1.0 data GCC ships, and matches the shipped file byte
  for byte.
- The CRC table in `libiberty/crc32.c` comes from the generator in its own
  comment and matches the shipped file.
- The DPD and BID decimal tables use the GCC 4.7 port's generators; every
  value matches the shipped tables.
- gengtype's scanner is regenerated with the bootstrapped Flex 2.6.4, which
  also produced the shipped copy. They match apart from the release manager's
  absolute path in `#line` directives.
- `cp/cfns.h` is gperf output upstream. `generators/gperf.awk` writes an
  equivalent lookup from `cfns.gperf` with the bootstrapped awk: a table
  sorted by name and searched by bisection. A test checks that it holds the
  same 414 names as the shipped gperf lookup, agrees with it for each, and
  rejects the same near misses. The GCC 4.7 port disabled this lookup instead.

Option records, pass instances and the x86 builtin types come from GCC's awk
scripts. `gcov-iov.h` records the generator's name rather than its action
path, and genmatch records `.` rather than its working directory; see
[patches](patches/README.md).

## Configuration

The GCC configuration headers are written as `gcc/mkconfig.sh` would write
them for x86_64 musl: `tm.h`, `tm_p.h`, `config.h`, `bconfig.h` and `tconfig.h`
come from config.gcc's file and define lists. `auto-host.h` is a reviewed list
of `gcc/config.in` values for a native musl 1.2.5 host with GNU binutils 2.30,
with the target-visible macros outside `USED_FOR_TARGET`, as config.in has
them. It uses release checking: assertions stay enabled, extra checks do not.
The support libraries share a reviewed `library-config.h`, and libgcc gets its
own `auto-target.h` and `libgcc_tm.h`.

Some choices differ from what configure would write:

- Only the C, C++ and LTO option files and the C and C++ tree codes and garbage
  collector roots are included. configure collects every front end present in
  the source tree.
- `multilib.h` describes one native x86_64 library directory, as in the GCC
  4.7 port. The driver's specs accept only static native executables and
  reject `-m32`, `-shared`, `-pie` and `-static-pie`.
- Split stacks are rejected: GCC 10 would use glibc's `%fs:0x70` slot, which
  musl's thread control block does not have.
- `ld` is never passed `--sysroot`, and the six 32-bit-only assembler probes
  are off, as a real configure against the x86_64-only binutils would find.

## Compilers and runtime

Each stage builds its own support libraries, generators and compilers from the
same sources. The first stage is built by GCC 4.7's `g++` and libstdc++; each
later stage by its predecessor's GCC 10 and libstdc++ 10. As upstream, each
stage keeps its compiler's default C++ dialect, and later stages add
`-Werror`. The compiler links GMP, MPFR, MPC, zlib and libbacktrace; the static
analyzer is enabled, as it is upstream.

The new driver builds libgcc, libgcov and the startup objects with upstream's
flags for x86_64 Linux: 238 libgcc objects with BID decimal float, soft
binary128, the x86_64 ms-abi stubs and CPU detection, 27 libgcov objects, and
`crtbeginT.o`, `crtend.o`, `crtprec{32,64,80}.o` and `crtfastmath.o`. As
upstream, the driver links `crtfastmath.o` for `-Ofast` and `-ffast-math` and
`crtprec32.o` to `crtprec80.o` for `-mpc32` to `-mpc80`, and the compiler's
include directory has libgcc's `unwind.h` and `gcov.h`. GCC 10 enables the
x86_64 signal-frame unwinder only for glibc; a one-line change enables it for
musl.

The C++ standard library is in [libstdcxx10](../libstdcxx10/README.md).

## Tests and stage comparison

Each stage's compiler, driver and runtime pass the same execution tests: C
and C++ front-end diagnostics, missing headers, tools and libraries,
preprocessing, the rejected link modes and split stacks, `-nolibc`, and
runtime programs at `-O0` and `-O2`. The runtime programs cover 128-bit and
complex arithmetic, signal-frame unwinding, extended precision, startup,
threads, `-pthread`, math, Unicode, and the floating-point modes the
`-ffast-math` and `-mpc32` startup files set. A coverage test compiles, runs
and reports an instrumented program with each stage's gcov, and another calls
libgcov through `gcov.h`. The installed libbacktrace notice is checked against
its source header.

Stage2 and stage3 compare byte for byte: 712 host objects (support libraries,
generators, compilers, drivers and zlib), the 238 libgcc and 27 libgcov
objects, the six startup objects and ten archives, together with the 189
libstdc++ objects and three archives. Only `cc1-checksum.o` and
`cc1plus-checksum.o` are excluded. The combined gate passes 1342 tests.
`audit-gcc-comparison.py` checks the comparison inventory, run as in the
[GCC 4.7 port](../gcc47/README.md) over this package and `libstdcxx10`.

```
buck2 test cellar//bootstrap/stage1/gcc10: cellar//bootstrap/stage1/libstdcxx10:
buck2 test cellar//bootstrap/stage1/gcc10:stage-comparison cellar//bootstrap/stage1/libstdcxx10:stage-comparison
```
