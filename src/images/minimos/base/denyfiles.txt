# Vendor sysctl files. systemd-sysctl reads /usr/lib/sysctl.d in the same
# pass as /etc/sysctl.d, so host-global keys left here would reach a
# docker host's kernel. Those keys belong in
# /usr/lib/minimos/sysctl-vm.conf, which only minimos-harden.service
# applies, and only on a VM.
#   50-coredump.conf points kernel.core_pattern at the culled
#     systemd-coredump and turns suid coredumps back on.
#   50-default.conf mixes kernel.sysrq, kernel.core_uses_pid and
#     fs.protected_* with network keys. 60-minimos-hardening.conf restates
#     the network half, and sysctl-vm.conf carries the rest at stricter
#     values.
#   50-pid-max.conf sets kernel.pid_max, which is host-global and lives in
#     sysctl-vm.conf instead.
/usr/lib/sysctl.d/50-coredump.conf
/usr/lib/sysctl.d/50-default.conf
/usr/lib/sysctl.d/50-pid-max.conf

# Vendor tmpfiles that provision the image from outside it.
#   provision.conf writes /etc/hosts and /root/.ssh/authorized_keys from
#     SMBIOS, fw_cfg or kernel command line credentials. minimos bakes
#     those files, and nothing outside the image may rewrite them.
#   static-nodes-permissions.conf makes /dev/{fuse,net/tun,kvm,vfio/vfio,
#     vhost-*} mode 0666 and names audio and kvm groups the baked
#     /etc/group lacks. A composition that needs one of those devices
#     should grant it with DeviceAllow= in its own unit.
#   20-systemd-shell-extra.conf links /etc/profile.d/70-systemd-shell-extra.sh
#     to a script this image doesn't ship.
/usr/lib/tmpfiles.d/provision.conf
/usr/lib/tmpfiles.d/static-nodes-permissions.conf
/usr/lib/tmpfiles.d/20-systemd-shell-extra.conf

# Vendor tmpfiles for culled daemons.
#   systemd-network.conf names the systemd-network account, which the
#     baked passwd doesn't have, and fails to resolve it on every boot.
#   systemd-resolve.conf has `L /etc/resolv.conf -> ../run/systemd/
#     resolve/stub-resolv.conf`. `L` leaves the baked resolv.conf alone
#     today, but an upstream switch to `L+` would point DNS at a stub no
#     resolved serves.
#   systemd-pstore.conf creates state for a denied binary.
#   20-systemd-ssh-generator.conf creates /run/sshd and links into
#     /usr/lib/systemd/ssh_config.d for the denied ssh proxy and
#     generator. The platform sshd reads none of it.
/usr/lib/tmpfiles.d/systemd-network.conf
/usr/lib/tmpfiles.d/systemd-resolve.conf
/usr/lib/tmpfiles.d/systemd-pstore.conf
/usr/lib/tmpfiles.d/20-systemd-ssh-generator.conf

# Bus policy for services this image doesn't have. Every daemon these
# describe is culled, or masked in the case of hostnamed.
# org.freedesktop.oom1.conf names a systemd-oom account the baked passwd
# lacks, and dbus complains about it on every boot. The rest grant
# send and receive rules for bus names nothing can own. Dropping

# /etc/passwd along with systemd-timesync.

# chrony's vendor units. minimos ships its own chronyd.service in
# /etc/systemd/system, which would outrank this one, but the vendor unit
