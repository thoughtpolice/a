# What a composition layer may write, as a default-deny policy that
# scratch_image.py enforces when minimos.image() stacks layers, and that
# the boot smoke re-checks on the finished image. One rule per line:
#
#   composable PREFIX   a composition may create new paths under PREFIX
#   sealed PREFIX       no composition may create anything under PREFIX
#
# Some rules come first and need no line here. A composition layer can
# never:
#
#   - replace a path a lower layer established. That covers every one of
#     the base's ~670 paths without naming them: PID 1, the shells, the
#     account files, every vendor unit.
#   - write a type-wide systemd drop-in directory such as `service.d` or
#     `user-.slice.d`, which would reconfigure units it does not own.
#   - write a unit file, mask, alias or drop-in in /etc/systemd/system for
#     a unit a lower layer already defines. systemd finds a unit by name
#     across its whole search path, so a new path there can override a
#     vendor unit the layer never touched. Links in `.wants/` and
#     `.requires/` stay open, since they only start a unit as its own layer
#     configured it.
#   - add a program to one PATH directory under a name a lower layer ships
#     in another. The image, the login shell and systemd each search those
#     directories in a different order.
#   - make a symlink of a sealed prefix, a PATH directory or a unit
#     directory, or of any directory above one. The rules judge each path
#     by where it resolves, and a link like /usr/local -> /opt/x would move
#     /usr/local/lib and /usr/local/bin under /opt all at once.
#
# Paths resolve through symlinks the way the kernel and the extractor
# resolve them, so a ".." in a link target climbs out of wherever the
# links before it led.
#
# The parent directory of every path a layer writes must be declared by
# that layer or one below it, the base included, so no directory's mode
# and owner are left to the extractor.
#
# On top of that, a new path must fall under a composable prefix. Naming
# the dangerous paths instead would miss any search directory nobody
# thought of, and here those are refused because nothing opened them.
# The longest matching prefix wins and ties are sealed, so a sealed line
# can carve a directory out of a composable subtree and a composable line
# can reopen one path inside a sealed one.

composable etc
composable home
composable opt
composable srv
composable usr/bin
composable usr/lib
composable usr/libexec
composable usr/local
composable usr/share
composable var

# Carved back out of the composable prefixes above. In these directories
# adding a single file changes identity, privilege or boot policy for the
# whole image. Everything outside the composable prefixes, such as /run,
# /root, /boot, /dev and the merged-usr links, is already refused and
# needs no line.

# Identity and authentication.
sealed etc/passwd
sealed etc/group
sealed etc/shadow
sealed etc/gshadow
sealed etc/subuid
sealed etc/subgid
sealed etc/nsswitch.conf
sealed etc/login.defs
sealed etc/pam.d
sealed etc/security
sealed etc/sudoers
sealed etc/sudoers.d
sealed etc/doas.conf

# Accounts created at boot. The base bakes /etc and masks systemd-sysusers.
sealed etc/sysusers.d
sealed usr/lib/sysusers.d

# The dynamic loader reads these before any program's first instruction.
sealed etc/ld.so.preload
sealed etc/ld.so.conf
sealed etc/ld.so.conf.d
sealed etc/ld.so.cache

# Kernel-facing configuration applied by early boot services.
sealed etc/sysctl.conf
sealed etc/sysctl.d
sealed usr/lib/sysctl.d
sealed etc/tmpfiles.d
sealed usr/lib/tmpfiles.d
sealed etc/modules-load.d
sealed usr/lib/modules-load.d
sealed etc/modprobe.d
sealed usr/lib/modprobe.d
sealed etc/binfmt.d
sealed usr/lib/binfmt.d
sealed etc/udev
sealed usr/lib/udev
sealed etc/environment
sealed etc/environment.d
sealed usr/lib/environment.d

# systemd's configuration tree holds system.conf and its drop-ins,
# journald and logind config, presets, generators, and the unit paths
# that outrank /etc/systemd/system, system.control and system.attached.
# It's sealed whole so a directory a later systemd adds is refused too,
# and the two unit trees a composition owns are reopened below.
sealed etc/systemd
composable etc/systemd/system
composable etc/systemd/user

# systemd's private directory holds PID 1, its helpers, the vendor unit
# tree and the generators. It's sealed whole for the same reason. One
# file is reopened, the helper user@.service binds to, because the base
# denies it and examples/dev culls it back in for its user manager.
sealed usr/lib/systemd
composable usr/lib/systemd/systemd-user-runtime-dir

# systemd searches /usr/local/lib for units, sysusers.d, sysctl.d,
# tmpfiles.d, environment.d, binfmt.d and modules-load.d, and the loader
# doesn't search it at all, so nothing a composition ships belongs there.
# A composition that needs a library directory under it can reopen that
# one directory by name.
sealed usr/local/lib

# minimos's own boot and login chain lives here.
sealed usr/lib/minimos

# Bus policy. The vendor files let every uid send to PID 1 and leave the
# refusal to systemd's own authorization checks.
sealed etc/dbus-1
sealed usr/share/dbus-1

# Trust roots and the factory tree systemd-tmpfiles copies from.
sealed etc/ssl
sealed etc/pki
sealed etc/ca-certificates
sealed usr/share/ca-certificates
sealed usr/share/factory
sealed usr/share/polkit-1
